## 발단

사용자 질문: "사용자가 질문했을 때 연관 질문(후속 질문)을 어떻게 가져오나?"

코드 추적 결과 — "연관 질문"은 코드베이스에서 **suggestions(후속 질문)**. 벡터 검색이 아니라 LLM이 생성한다. 두 경로:
- 비스트리밍 `generate()` (`generator.py:101`): `suggestions_enabled=True`면 답변과 후속 질문을 한 번의 JSON 호출로 동시 생성. 청크가 같은 호출 context에 들어 있음.
- 스트리밍 `generate_stream()` + `generate_suggestions()` (`generator.py:156`, `:187`): 답변을 토큰 스트리밍한 뒤, 별도 LLM 호출로 후속 질문만 생성. 이 경로는 `question + answer`만 입력받고 **청크를 보지 않음**. TASK-024에서 첫 토큰 지연을 줄이려고 분리한 구조.

가드: 답변이 "정보 없음"류(`INSUFFICIENT_MARKERS`)면 후속 질문 강제로 비움. JSON 파싱 실패 시 빈 배열로 graceful degrade.

## 핵심 문제 진술 (사용자)

> "생성된 질문이 기존 내용에 입각한 것보다 LLM이 그냥 만들어낸 듯한 느낌이다."

원인 진단:
1. **재료 손실** — 스트리밍 경로는 청크 없이 답변만 본다. 답변은 이미 책 본문의 추상화 결과 → 거기서 질문을 파생하면 2차 추상화. 책 고유 디테일(인물·사건·개념·페이지)이 소실되어 "어느 책에나 통할 일반 질문"이 나온다.
2. **프롬프트가 상상을 요구** — `_SUGGESTIONS_SYSTEM`, `SYSTEM_PROMPT_WITH_SUGGESTIONS` 모두 "a user might naturally ask next" 표현. grounding이 아니라 LLM의 통념을 요청. 비스트리밍 경로는 청크가 context에 있어도 활용 지시가 없다.
3. ISSUE-007과 동일한 근본 문제 — LLM이 상상한 질문 ≠ retrieval이 실제 답할 수 있는 청크.

## 검토한 선택지

- **답변 기반(현행)**: 대화 맥락 자연스러움. 그러나 grounding 약함 — 위 문제의 원인.
- **청크만 기반**: 탐색 폭 ↑. 그러나 답변과 동떨어진 질문 위험, 대화 맥락 약화.
- **하이브리드(답변+청크)**: 답변은 맥락·중복 회피용, 청크는 "답 가능" 보장용. ISSUE-007 교훈과 정합.

grounding을 강제하는 레버:
- 레버 A — 프롬프트 어휘를 상상 → grounding으로 교체. 비용 0.
- 레버 B — 각 질문에 `source`/`evidence`(청크 근거 구절)를 함께 출력. evidence가 청크에 없으면 폐기. "만들어낸 질문"을 거르는 핵심 장치이자 디버깅 수단.
- 레버 C — 생성 질문을 retrieval에 재투입해 점수 미달 폐기. 가장 확실하나 질문당 검색 1회 추가로 지연·비용 큼.

## 스트리밍 경로의 청크 확보 방식 (사용자 확인 질문)

"스트리밍 경로에서 청크를 어떻게 다시 가져오나?" → **재검색 불필요.** `chunks`는 `pipeline.py:290` `retrieve()` 한 번으로 만든 로컬 변수이고, 같은 메서드 스코프에서 `generate_stream`(`:335`) 등에 이미 재사용된다. `generate_suggestions` 호출(`:343`) 시점에도 살아 있으므로 인자 1개만 추가하면 된다. "다시 넣는다"는 데이터 재검색이 아니라, 별도 LLM 호출의 입력 프롬프트에 청크 텍스트가 다시 직렬화되어 입력 토큰으로 과금된다는 뜻.

## 비용·성능 추정 (실측 기반)

`answers_2026-05-14` eval(12쿼리, gpt-4o-mini) 실측:
- 질문 median 23자, 답변 median 615자, retrieve 청크 4개·총 1,625자, 현재 쿼리 지연 median 5.7초.

스트리밍 `generate_suggestions` 별도 호출:
- 현재: 입력 ~1,140토큰 + 출력 ~80토큰 ≈ $0.00022/호출
- 보완 후: 입력 ~3,840토큰 + 출력 ~300토큰 ≈ $0.00082/호출 → **+$0.0006, 약 3.7배**
- 절대값 작음: 1,000질의/일도 월 +$18, 100질의/일이면 월 +$1.8. 새 API 키·새 모델 없음.

비스트리밍 `generate()`: 청크가 이미 context에 있어 추가 비용 ≈ 0.

지연: 청크 입력 prefill +0.3~0.5초로 작음. 주 요인은 출력 토큰 증가(source/evidence) — 후속 질문 칩이 "답변 후 +1~2초" → "+3~5초". evidence 길이 제한·폐기 여유분 최소화로 +2초 이내로 억제 목표.

⚠️ eval 셋 12쿼리로 표본 작고 청크가 작게 나온 편 — 운영에선 청크 토큰이 더 클 수 있어 비용 추정 상향 여지.
